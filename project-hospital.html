Hospital Management System

A desktop application for managing hospital operations — patients, doctors, appointments, and medical records — built with Python and object-oriented design principles.

My role: GUI / UX Design

01 Overview

This project is a full-featured desktop application for managing day-to-day hospital operations: registering patients and doctors, scheduling appointments, and maintaining medical records — all backed by a database and wrapped in a usable graphical interface.

02 Problem Statement

Small clinics and hospital departments often rely on paper records or scattered spreadsheets to track patients, doctors, and appointments, which makes information slow to retrieve and easy to lose. The goal was to centralize these operations in a single, reliable desktop tool.

03 Solution & Features

  • User authentication to control access to hospital records
  • Patient management — registration, lookup, and history
  • Doctor management with department and schedule tracking
  • Appointment scheduling between patients and doctors
  • Digital medical records with CRUD (create, read, update, delete) operations
  • Database integration for persistent, structured storage
  • A graphical interface built for non-technical hospital staff to navigate easily

04 My Responsibilities

I focused on the GUI and user experience layer of the application — designing the interface flow so that staff could move between patient records, doctor schedules, and appointments without confusion, and making sure forms and views stayed clear and consistent across the app.

05 Architecture & Technologies

Built with Python using object-oriented principles to separate concerns between the data layer (patients, doctors, appointments, records) and the presentation layer (the GUI). A relational database handles persistent storage, with standard CRUD operations underpinning every screen.

06 Challenges

Keeping the interface intuitive while surfacing a large amount of interconnected data (patients ↔ doctors ↔ appointments ↔ records) required careful layout decisions and consistent navigation patterns.

07 Lessons Learned

Working on this project reinforced how much interface design affects whether a functional system actually gets used well — clean structure and OOP separation made it much easier to iterate on the UI without breaking the underlying logic.

08 Future Improvements

  • Role-based access control (admin, doctor, receptionist views)
  • Exportable patient reports (PDF)
  • Migrating the GUI to a modern framework for a more polished look
